Client / Developer Project Report

Reflections on my three roles in the team project: client, lead developer, and junior developer.

Client Report

As the client for my own portfolio site (built by Student1's team), I chose content and images that matched my elevator pitch. For example, I picked project screenshots of the rafting and gallery builds because they best show layout and optimization skills, plus a simple JJ logo for a clean brand.

We communicated over Microsoft Teams and I shared my site plan as a document. Communication was smooth overall; the only hiccup was a short delay getting the live URL after the first publish. My developer met expectations and followed my wireframe closely — the hero and featured-projects layout matched my sketch. Next time I would hand over all final images up front instead of sending some later, to avoid mid-project swaps.

Site: student1.github.io/wdd130-jensen

Lead Developer Report

As lead developer building Student2's site, I shared the site plan and assigned each junior a specific page — Student3 on About, Student4 on Contact — with clear deadlines in Teams. I checked in with my client after each milestone; one early mix-up about colors was resolved by simply sharing the published page.

I created the repository, enabled GitHub Pages, and sent the client the live URL after every update (also posting it in the repo About section and README). Working with GitHub was smooth once set up; the main learning curve was coordinating pushes so teammates didn't overwrite each other.

Site: github.barefootbetters.com/wdd130-student2

Junior Developer Report

As a junior developer on two teams, I communicated with both leads over Teams and they were responsive. I always knew what was expected — each lead told me which page to build (an About page for Student5, a Gallery page for Student6) and shared the team stylesheet.

I was able to contribute fully, coding and styling both assigned child pages with each team's shared CSS. To avoid GitHub issues I pulled before editing; one merge conflict came up and I fixed it by pulling and re-applying my changes.

Sites: Student5's site · Student6's site

General Experience & Reflections

The most challenging part was coordinating GitHub across several people without overwriting work; I overcame it by always pulling before pushing and announcing when I pushed. What I enjoyed most was watching a wireframe become a live, hosted site — especially publishing with GitHub Pages.

If I did it again, I would set clearer image and content deadlines up front and agree on a branching approach earlier. Overall I feel more confident about real-world projects: playing all three roles — client, lead, and junior — gave me a realistic picture of the full workflow, from planning through deployment.
